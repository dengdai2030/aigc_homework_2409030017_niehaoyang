# 第 8 周 · 答辩稿与演示脚本

> 总时长 10 分钟：演示 5 分钟 + 讲解 3 分钟 + 问答 2 分钟
> 核心原则：**先给结果，再讲怎么做的。** 老师看的是"东西能不能用"，不是"你写了多少行"。

---

## 一、开场（40 秒，站着说，不切页面）

> 我做的是一个多模态儿童故事生成流水线。
> 输入一句话，比如"一个怕黑的小女孩在阁楼点亮旧灯笼"，
> 输出是一本 11 页的绘本 PDF、一段 4 分 52 秒的四人配音有声书、
> 和一条 4 分 53 秒带字幕的短片。
>
> 三种模态里，小女孩是同一个孩子——同一张脸、同一件星星睡衣、同一只掉了耳朵的兔子。
>
> 我先把成品放一遍，再讲我是怎么让它跑起来的。

---

## 二、现场演示（5 分钟，严格按这个顺序）

### 0:00–0:40　绘本（PDF 全屏翻）

- 打开 `outputs/book/把光借给你.pdf`
- 停在第 1 页（封面）：**"标题是画在图里的，不是另起一页——因为第一版就是图一页、字一页，特别难看。"**
- 翻到第 2 页（角色介绍）：**"这一页是角色设定图，它不只是给孩子看的，它是我后面 8 张图的'参考图'。"**
- 快速翻第 3–6 页：**"注意看，女孩的发卡、睡衣、兔子玩偶，每一页都在。"**

### 0:40–2:00　有声书（网页版）

- 打开 `outputs/web/audiobook.html`，点播放
- **"左边这张图会跟着场景换，右边是高亮到哪句。"**
- 停 20 秒，让老师听到**四个不同音色**：旁白（女声慢）、小满（少女音）、阿灯（年轻男声快）、墨墨（低沉慢）
- 指着墨墨那句：**"墨墨的基础语速是 −14%，加上'悲伤'再减 15%，实际是 −29%。所以它一开口就是丧的。"**
- 点任意一句：**"点哪里就从哪里播，方便反复听。"**

### 2:00–3:30　视频

- 打开 `outputs/video/把光借给你_故事短片.mp4`，跳到 0:14 和 2:30 各看 15 秒
- **"画面是缓慢推近的，8 个镜头推拉方向交替，不然会像 PPT。"**
- **"字幕是按标点断的——第一版按 20 字硬切，出现了'窗帘被风吹得鼓 / 起来'，把词劈开了。"**

### 3:30–4:10　故事网页（作业0）

- 打开 `src/week0_web/index.html`
- 改名字、改兴趣、换一个世界，点"开始讲故事"
- **"第一周只做了这个网页，四套主题、四套 SVG 插画，纯前端，双击就开。"**

### 4:10–5:00　Agent（作业6）

- 终端跑 `python scripts/run_week6.py`
- **"六步：检索素材 → 写故事 → 配图 → 配音 → 剪片 → 排版。"**
- 打开 `outputs/traces/log_案例2.md`：**"每一步的工具、耗时、产物都在这。改名字那次，只重跑了配音、剪辑、排版三步，图片一张没重做——因为图片里主角的脸没变，凭什么重画。"**

> **备用方案**：如果现场网络断了、Edge TTS 挂了，直接放 `outputs/video/` 里的成片，
> 并说明"这一步需要联网，所以我提前跑好了"。
> 所有产物都是本地文件，最坏情况下演示不会中断。

## 三、讲解（3 分钟，只讲三件事）

### 3.1 架构：一条主干，四个纯函数（60 秒）

```
创意 → story.json ─┬→ 图 → 绘本
                   └→ script.json → timeline.json ─┬→ 有声书
                                                   ├→ 字幕
                                                   └→ 视频
```

> "整个项目只有两个'主干数据'：story.json 和 timeline.json。
> 其它所有产物都是它们的纯函数。
> 这样做的好处是：任何一步挂了都能单独重跑，不会污染上游。
> 也是因为这一点，第 7 周的 Agent 才能把六个模块当成六个工具串起来。"

### 3.2 三个关键决策（90 秒）

**① 角色一致性：特征卡 + 固定 seed + 参考图，不做 LoRA**

> "8 个场景做 LoRA 不划算。我把角色外貌写成一段不可变的文本，
> 每次生成原样拼进 prompt，再用设定图当参考图。
> 结果 8 张图、四个特征项全中。
> 中间踩过一个坑：特征卡第一版写'活泼可爱'，画出来每张都不一样；
> 改成'左侧别一枚红色小发卡''抱一只掉了左耳的兔子玩偶'才稳定。
> **Prompt 要具体到能被画出来。**"

**② 视频：剪辑式而不是生成式**

> "视频模型生成 8 段大概三五十块，而且角色会漂。
> 但我拒绝它主要不是因为钱——
> 是上一周刚把角色一致性做出来，用视频模型重画一遍就全毁了。
> 所以选 FFmpeg 把插图剪成视频，Ken Burns 缓慢推拉，成本 0，完全可复现。"

**③ 时间轴是唯一事实源**

> "字幕、配音、画面要同步，我的做法是在 TTS 阶段就把每句音频解码成 PCM、
> 用 wave 读帧数算出毫秒级时长，累加成 timeline.json。
> 视频剪辑和字幕烧录都只读这一份，所以不可能错位。
> 顺带说一句：我不用 ffprobe，因为 imageio-ffmpeg 只带 ffmpeg 不带 ffprobe，
> 用 wave 读帧数反而更准。"

### 3.3 一个诚实的取舍（30 秒）

> "我做的所有环节都有降级方案：没有 API Key 就回放已经生成好的样本，
> 没有 CLIP 就用 TF-IDF 加颜色直方图。
> 这不是偷懒，是因为交作业的第一原则是'老师打开就能跑'。
> 但降级是有代价的——比如图像检索在降级模式下本质是'用文字找图'，
> 我测了 5 个查询，'怕黑的小女孩'那条召回率只有 0.5，
> 因为'怕黑'这个抽象词它抓不住。这个数字我如实写在报告里了。"

## 四、问答准备（10 个问题，按被问概率排序）

**Q1：这算 Agent 吗？还是就是一个流水线脚本？**
> 严格说，规划是确定的 DAG，不是 ReAct 那种"边想边试"。
> 但 Agent 的核心不是"随机应变"，是**工具调用 + 状态记忆 + 可干预**。
> 我的实现里：工具有注册表和 schema；上一步的产物会自动接到下一步的入参（这是记忆）；
> 用户中途说"把主角改成小树"，它能解析意图、判断影响范围、只重跑下游三步。
> 另外我留了 `LLMPlanner`，配置 Key 之后可以让模型自己拆步骤。
> 所以它是"有规划的 Agent"，不是"会瞎试的 Agent"——我认为后者在内容生产里反而是缺点。

**Q2：CLIP 你根本没用上，为什么还留着？**
> 用上了，只是这台机器上没装 torch。
> `library.py` 里 `build_library()` 会先尝试 `ClipEncoder`，失败才降级。
> 留着它是因为降级方案有个明确的短板：抽象语义抓不住。
> 报告里 Q2 的召回率 0.5 就是证据。装了 CLIP 之后这一条会明显改善。

**Q3：角色一致性你怎么证明不是碰巧？**
> 三个层次：一，我把四个特征项（发型/发饰/服装/随身物）逐场景打勾，8/8 全中；
> 二，把 8 张图缩到 200px 排成一行看有没有"跳出来"的那张——缩略图下细节全没了，
> 只剩造型和配色，漂移会立刻暴露；
> 三，还有两张失败图我留着没删，就是 prompt 迭代前后的对比证据。

**Q4：故事是你写的还是 AI 写的？**
> 大纲和取舍是我定的（怕黑→理解恐惧→把光分出去这个结构），
> 具体文字是 AI 按 S4 策略生成的，我改了结尾一句、删了两处说教。
> `ai_log.md` 里写了占比估算：故事文本约 85% AI、15% 人工。
> 我的判断标准是：**这段文字如果被追问"为什么这么写"，我能不能答上来。** 答不上来的就重写。

**Q5：为什么不直接用现成的绘本生成工具？**
> 现成工具解决的是"一次生成"，我解决的是"可复现地生成"。
> 比如同一个 seed 能重出同一张图、timeline 能重剪出同一支片子、
> Agent 能只重跑受影响的三步。这些是工程问题，不是生成问题。

**Q6：成本多少？**
> 离线模式 0 元。在线模式大约 1.4 元：8 张图约 1.1 元，文本约 1.2 万 token 约 0.03 元，
> TTS 和视频都是本地免费。时间上全流程约 8 分钟，其中视频编码占 5 分钟。

**Q7：视频 108MB 是不是太大了？**
> 是。1080p、293 秒、crf 21，码率 3.1Mbps。
> 交作业够用，发微信不行。要压的话 crf 26 大约 60MB，或者出 720p 版本。
> 我保留 1080p 是因为投屏演示时清晰度更重要。

**Q8：你的 Prompt 对比实验，四种策略是同一个模型跑的吗？**
> 是。同一模型、同一 temperature、同一输入，只有 Prompt 不同。
> 原始返回都在 `data/raw_outputs/`，`evaluate.py` 可以复算全部指标。
> 需要说明的是，这台机器没配商用 Key，四份输出是由内置模型按四份 Prompt 原文执行的。

**Q9：如果让你再做两周，你会做什么？**
> 三件事，按优先级：
> 一，把 S3 的人设注入 S4 的结构，拿文学性又不丢合规；
> 二，给 Agent 加一个 LLM 解析器，让它能听懂"换个更开心的结尾"这种创意类干预；
> 三，检索加 query 改写，这是提升召回最便宜的一招。

**Q10：这个项目最难的地方是什么？**
> 不是任何一个技术点，是**接口**。
> 我这次 8 个 bug 里 5 个是"两个模块各自都对，拼起来就错"——
> 命名不一致、向量空间不一致、路径基准不一致。
> 而且都是跑一次端到端才暴露的。
> 所以我现在写代码的顺序改了：先把接口定死，先写最小端到端脚本，再填实现。
